# How the profile art is generated

Everything on the profile is a **self-contained animated SVG**. GitHub strips
`<script>` from READMEs and blocks external CSS, but it renders SVGs embedded via
`<img>` and plays their SMIL / CSS-keyframe animations — so all the motion lives
inside the SVG files themselves.

| File | Generated by | Refreshed |
| --- | --- | --- |
| `contrib-heatmap.svg` | `fetch_contributions.py` → `render_heatmap_svg.py` | **daily, by CI** |
| `ascii-portrait.svg` | `prep_photo.py` → `make_ascii_svg.py` | manually, when the photo changes |
| `info-card.svg` | `make_info_card.py` | manually, when the details change |

## Daily automation

`.github/workflows/update-profile-art.yml` re-scrapes and re-renders the heatmap on
a cron and commits the result. It only needs `scripts/requirements.txt`
(`requests` + `beautifulsoup4`) — the heavy image libraries are never installed in CI.

No personal access token is required: the calendar comes from the public HTML
fragment at `https://github.com/users/<username>/contributions`, the same one the
profile page itself uses.

## Regenerating locally

```bash
python -m venv .venv && . .venv/Scripts/activate     # Windows
pip install -r scripts/requirements.txt

python scripts/fetch_contributions.py                # -> data/contributions.json
python scripts/render_heatmap_svg.py                 # -> contrib-heatmap.svg
```

### The ASCII portrait

Needs the extra image libraries, and only ever runs on your machine:

```bash
pip install -r scripts/portrait-requirements.txt

python scripts/prep_photo.py source-photo.jpg        # -> source-prepped.png
python scripts/make_ascii_svg.py --cols 100          # -> ascii-portrait.svg
```

`prep_photo.py` does the three things that make a face readable as ASCII: cuts the
background out (`rembg`), boosts local contrast (CLAHE), and composites onto pure
white so the background lands on the blank end of the ramp. `rembg` and
`opencv-python` are optional — the script warns and degrades if they're missing.

Two notes on `rembg`: install it as `pip install "rembg[cpu]"`, because plain
`rembg` skips the `onnxruntime` backend and the import fails at runtime. And its
first run downloads a **~1 GB** model (`bria-rmbg-2.0`) into `~/.rembg/models/`, so
give it a few minutes.

Background removal is genuinely load-bearing for a studio portrait — it isn't
optional polish. This photo's vignette backdrop spans grey 91–212 while the face
spans 100–180, so the two ranges overlap completely: no threshold, white-point
stretch, or flood fill can separate them. Only real segmentation works.

Dialling it in:

| Symptom | Fix |
| --- | --- |
| Dark unreadable blob | `prep_photo.py --clip 3.5` or `make_ascii_svg.py --gamma 1.3` |
| Too faint / washed out | `make_ascii_svg.py --gamma 0.8` |
| Background still printing | make sure `rembg` is installed, or shoot against a plain wall |
| Too wide for the README column | lower `--cols` (each column ≈ 4.2px at the default font size) |

No photo yet? `make_ascii_svg.py --text "DIPANSHU" "POONIA"` renders a wordmark
through the exact same pipeline as a placeholder.

### The info card

Edit the `CARD` dict at the top of `make_info_card.py` — that's the only part meant
to be touched — then:

```bash
python scripts/make_info_card.py
STATIC=1 python scripts/make_info_card.py            # frozen frame, for previews
```

## Previewing

```bash
python -m http.server 8899
```

then open <http://127.0.0.1:8899/preview.html>. It lays the three SVGs out exactly
like the README does; reload to replay the animations.

## Layout note

The widths are meant to line up: the heatmap is `860`, and the two README columns
are `370 + 490`. If you change one, change the others.

## Gotchas that cost time

- Inline `style="..."` in a README is stripped. The only vertical spacing GitHub
  honours is `<br>`.
- `<h1>`/`<h2>` draw a full-width underline rule. Use `<h3>` when you don't want it.
- `<table>` is the only reliable way to put two images on one row.
- GitHub proxies README images through its camo cache, so a freshly committed SVG
  can take a few minutes to appear on the profile page.
